# BlockProt Reloaded 1.3.4-hotfix.1

## Summary

1.3.4-hotfix.1 is a hotfix on top of the 1.3.4 release. It fixes the critical startup crash on Spigot 26.2 servers (`NoClassDefFoundError: net/kyori/adventure/text/Component`) that prevented the plugin from enabling, the second wave of Paper-only runtime crashes that appeared once the plugin could enable, and the inventory-menu issues reported from the Spigot live test: two `NoSuchMethodError` crashes when opening the block info panel and the friend search sign prompt, menu buttons that ran commands printing `usage: /bp <user/admin>` instead of doing anything, and back buttons closing the whole menu instead of returning to the previous window.

Paper, Folia, and Purpur are unaffected by the hotfix. CraftBukkit remains hard-blocked: the plugin refuses to enable on it, so the hotfix's Spigot fixes do not apply there.

## What Failed & How It Was Fixed

### Spigot startup crash (`NoClassDefFoundError`)

- **Symptom:** On Spigot 26.2, enabling the plugin threw:
  ```text
  java.lang.NoClassDefFoundError: net/kyori/adventure/text/Component
          at de.sean.blockprot.bukkit.BlockProt.onEnable(BlockProt.java:202)
  Caused by: java.lang.ClassNotFoundException: net.kyori.adventure.text.Component
  ```
- **Root cause:** Spigot and vanilla CraftBukkit do not ship Kyori Adventure and do not expose `sendMessage(Component)`, `sendActionBar(Component)`, or `ItemMeta#displayName(Component)`.
- **Fix (commits `087b4b0`, `d09e08e`, `2dc438f`):**
  - Added `ComponentMessages` ([`087b4b0`](https://github.com/VictorGugug/BlockProt-Reloaded/commit/087b4b0fc0747ffdd218c15971bc7d59395eb5b0), [`d09e08e`](https://github.com/VictorGugug/BlockProt-Reloaded/commit/d09e08eb34bb1ee8cdbf61268ee7041cfb4dfb4d)), a runtime wrapper that checks via reflection whether the server exposes Adventure component methods. On Paper, Folia, and Purpur it calls the native APIs; on Spigot and CraftBukkit it serialises to legacy colour-coded strings and calls the plain-string equivalents.
  - Updated `spigot/build.gradle.kts` ([`2dc438f`](https://github.com/VictorGugug/BlockProt-Reloaded/commit/2dc438f88f79d47c5c29de69281914427bd83bae)) to shade all required `net.kyori` transitive dependencies (`adventure-api`, `adventure-key`, `adventure-text-minimessage`, `adventure-text-serializer-legacy`, `adventure-text-serializer-plain`, `option`, `examination-api`, `examination-string`) so Spigot/CraftBukkit environments can resolve Adventure classes at runtime.

### Spigot runtime crashes found after the startup fix

Fixing the startup crash let the plugin enable on Spigot, but live testing on Spigot 26.2 then surfaced a second wave of Paper-only API calls that crashed at runtime instead of at startup. All of the following are now guarded with a Spigot-compatible fallback:

- `DefaultConfig.isWorldExcluded` called a Paper-only `NamespacedKey` accessor unguarded, breaking most block events (place, break, burn, redstone).
- `SkinCache.getOrFetchAsync` called a Paper-only `Bukkit.createProfile` overload unguarded on every player join.
- `BlockProtInventory.createInventory` called a Paper-only `Bukkit.createInventory` overload unguarded, breaking every inventory GUI.
- `BlockNBTHandler`'s constructor and NBT-mutation methods called a Paper-only `Block#getState(boolean)` overload unguarded, breaking block locking, friend management, and renaming for chests, doors, beds, and other tile-entity blocks.
- Several inventory classes (the player-head skull rendering in the friends list, block/entity info panels, and the audit log) referenced Paper's `com.destroystokyo.paper.profile.PlayerProfile` type directly, which does not exist on Spigot. These now use the standard Bukkit `org.bukkit.profile.PlayerProfile` API instead.
- The server-side anvil text input used for renaming a locked block, searching for a friend to add, and a few other in-menu text prompts relied on `Player#openAnvil`, a Paper-only method. On Spigot, this silently disabled all of those prompts instead of opening them. The input now falls back to a standard virtual anvil inventory (`Bukkit.createInventory(..., InventoryType.ANVIL, ...)`) on servers without `Player#openAnvil`, so renaming a block and the other anvil-based prompts work on Spigot too.

### Cross-platform action bar safety

Calls to `player.sendActionBar(...)` across commands and inventory handlers now go through `ComponentMessages`. On servers that do not support the action bar API the call falls back to a plain chat message instead of throwing `NoSuchMethodError`.

### Action bar safety sweep (working tree, uncommitted)

The remaining direct `player.sendActionBar(Component)` call sites across dialogs, inventories, listeners, and commands now go through `ComponentMessages.sendActionBar`, which falls back to a legacy colour-coded string on servers without the Component action bar API instead of throwing `NoSuchMethodError`. This closes the last Spigot runtime crash class found in live testing (the action bar equivalents of the `sendMessage(Component)` crashes fixed earlier).

### Menu & Navigation Fixes

#### Menu buttons no longer print `usage: /bp <user/admin>`

With `use_menus: true` (inventory menus, no dialogs), several buttons on the user and admin menu ran `/blockprot` subcommands via `performCommand`. Because the plugin's CLI subcommands are disabled in menu mode, those buttons fell through to the usage text and did nothing. They now execute their action directly:

- **User Menu > Transfer** (`/bp transferall`): now prompts for the target player (chat input on Paper, sign input on Spigot) and transfers every owned block to that player.
- **User Menu > About** and **Admin Menu > About** (`/bp about`): prints the same version/credits/issue-report summary the command prints in non-dialog mode.
- **Admin Menu > Config** (`/bp admin`): opens the in-game config editor when the dialog API is available; on Spigot it shows a hint instead of falling back to the admin menu.
- **Admin Menu > Auto Drop**: opens the Auto Drop inventory directly (it used to reopen the admin menu).
- **Admin Menu > Debug** (`/bp debug run`): runs the diagnostics suite directly.

#### Back buttons return to the window you came from

The menu system previously tracked only a single "origin" menu, which child menus overwrote, so back buttons closed the whole menu or skipped levels. `InventoryState` now keeps an origin **stack**: every menu pushes its own origin before opening a submenu, and `goBack` pops it, restoring the exact parent window. The push wiring now covers every hop in the inventory GUI:

- Admin Menu -> Lockables -> Auto Drop / Worlds: back returns to Lockables, then to the Admin Menu.
- Admin Menu -> World Protection Delete -> confirm: the delete screen and its confirm screen keep the navigation state, so back from the confirm returns to the world selector and back from the selector returns to the Admin Menu (previously both closed everything).
- Admin Menu -> Stats -> stat lists, and Admin Menu -> Info -> player's block list: back walks the chain level by level.
- `/bp info` -> player list -> player's block list: back returns to the player list (previously jumped to the Admin Menu).
- User Menu -> Settings / Friends / Stats, Settings -> Friends, Friends -> friend detail: back walks the chain level by level.
- Lockables -> Worlds -> world detail, and Auto Drop -> per-family list: back returns to the worlds list / Auto Drop.
- Block lock submenus (friends, settings, info, audit, inspect) push `BLOCK_LOCK`, keeping the block context intact when navigating back.
- Back buttons across all these flows now correctly re-render the parent with a Close button instead of a stale Back button.

#### Spigot crashes in menus (live test reports)

- **Block info panel crash** (`NoSuchMethodError: com.destroystokyo.paper.profile.PlayerProfile org.bukkit.entity.Player.getPlayerProfile()` in `BlockInfoInventory.fill`): the owner-skull skin lookup now guards the Paper-only `Player#getPlayerProfile()` and falls back to `Bukkit.createProfile` (itself guarded), so the friends list of a locked block opens on Spigot.
- **Friend search sign prompt crash** (`NoSuchMethodError: void org.bukkit.block.sign.SignSide.line(int, net.kyori.adventure.text.Component)` in `SignInput`): writing the prompt line now falls back to the legacy `Sign#setLine(int, String)` when the Component overload is missing.
- **Entity friend search input** used the Paper-only chat input unguarded in the entity friends menu; it now uses the same chat/sign/anvil fallback chain as the block friend search.

### Update notifications & version channels (commit `f7e16cb` + working tree)

The version scheme and update notifications were reworked so every message an admin or player sees tells them exactly what kind of build is available:

- **`SemanticVersion` now ranks versions in three tiers:** experimental pre-release builds (snapshot / bedev / BEDev, with `bdev` and `SNAPSHOT` kept as legacy aliases), clean releases, and post-release corrections (hotfix / patch / fix) ranked above the release they fix. The old alpha/beta/rc/dev special-casing is gone; those suffixes now rank as plain releases. A new `baseVersion()` accessor returns the numeric version a hotfix corrects (e.g. `1.3.4-hotfix` -> `1.3.4`).
- **Channel-aware update messages.** Stable servers see "New stable version: X" and are never offered experimental builds. Hotfix messages (in-game, console, log, and the Update dialog) now state the base version they correct through the `{base_version}` placeholder, e.g. "It fixes bugs from the current release (1.3.4)". BEDev messages are explicit that the build is experimental, not a stable version, and only published on GitHub.
- **Boot build announcement.** On startup the console prints which channel the server is running: "Running stable release X.", "Running hotfix X of the current release (Y).", or "Running experimental development build (BEDev) X. It is NOT a stable version; a safety backup has been created."
- **Safety backup on experimental builds.** When the running build is a pre-release (BEDev/snapshot), a backup is created at startup (in addition to the migration backup) whenever `enable_backups` is true.
- **Block Info shows the custom block name.** The block info inventory now displays the block's custom name as the primary title with the material as secondary lore, and the block info dialog shows a "Name" row when a custom name is set (new `INVENTORIES__BLOCK_INFO__NAME_LABEL` key, added to the English and Spanish translation files).

### Server software detection at startup (working tree)

The plugin now detects which server software it is running on and warns when it is not Paper or a Paper fork:

- **Detection.** `VersionCompat` reports the real software name via `Bukkit.getName()` (Paper, Purpur, Folia, Leaf, Spigot, CraftBukkit, and so on) and classifies the server with `isPaperFamily()`: true when the Paper API is present (every Paper fork ships it) or when the name is on the known Paper-fork list (Paper, Purpur, Folia, Pufferfish, Leaf, Leaves, Gale). The startup diagnostic now prints the real software name instead of the previous Paper/Spigot guess.
- **Warning on non-Paper software.** On Spigot, CraftBukkit, hybrid, or unknown software, the console shows a warning naming the unsupported software and recommending Paper or a Paper fork. The warning is non-fatal: the plugin still loads with its existing fallbacks. Pure CraftBukkit remains hard-blocked as before. Support for Spigot and Bukkit is planned to end in 1.3.6 (see the next section).
- **Paper-family forks supported without changes.** Besides Paper, Purpur, Pufferfish, and Folia, the plugin already runs unchanged on any Paper fork: Leaf (Winds-Studio), Gale, Leaves, and the smaller Paper forks that inherit the Paper API.

### Planned end of Spigot and Bukkit support (1.3.6)

Starting with version 1.3.6, BlockProt Reloaded will drop support for Spigot and vanilla Bukkit and will target Paper and Paper-based forks (Paper, Purpur, Pufferfish, Folia, Leaf, Gale, Leaves, and other Paper forks) exclusively. I will begin work on a separate project, BlockProt Reloaded Legacy, to keep supporting Spigot, Bukkit, and older Minecraft versions (from around 1.21 down to 1.19 or earlier) for anyone who still needs it.
