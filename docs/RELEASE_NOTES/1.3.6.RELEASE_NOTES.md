# BlockProt Reloaded 1.3.6 Release Notes

Welcome to BlockProt Reloaded 1.3.6. This release focuses on comprehensive performance optimizations, memory bounding, FoliaLib scheduler unification across all asynchronous tasks and GUI updates, dialog navigation grid stabilization, dead code cleanup, and expanded language support.

## Highlights

- **Multi-Tier Admin Hierarchy and Granular Permissions**: Introduced a configurable 4-tier admin permission hierarchy (`t1`, `t2`, `t3`, `owner`) plus custom actions (`admin_tiers.enabled`), supporting standalone staff management via `/bp tiers [setrole] <player> <role>` and player NBT without LuckPerms, as well as in-game Owner execution of `/bp recommended`.
- **Comprehensive Player Simulation and Headless Server Diagnostics**: Expanded `/bp debug run` with Domain 10 (Player Simulation & Gameplay Verification) testing 10 realistic in-game player scenarios (block lock lifecycle, stranger access denial, friend management, redstone toggles, family expressions, hazard protection, entity protection, GUI state theft prevention, permission evaluation, and player settings persistence) with zero persistent side effects. Added console headless execution (`/bp debug run [player]`), allowing server operators to run diagnostics without an active player and automatically targeting online players when available.
- **Player Persistent NBT Reorganization**: Cleanly categorized player preferences, friend entries, search history, and admin data into nested PDC compounds (`BukkitValues/blockprot/...`), with automatic legacy flat tag migration and deletion for clean viewing in NBTExplorer.
- **Action Bar Notification Persistence and Raid Alert Debouncing**: Refined `TemporaryActionBar` for sustained client alerts with configurable duration (`action_bar.duration_seconds: 6`). Optimized `RaidDetectionListener` with `ProtectedBlockCache` early exit and 5-second owner debouncing to prevent alert spam during raids.
- **Expanded Entity Protection**: Added `protectable_entities` in `blocks.yml`, enabling protection for non-tameable entities with `VILLAGER` configured as the currently supported and compatible entity type.
- **Modernized GitHub Actions CI, Automated Governance, and Dependency Audit**: Replaced legacy, unmaintained workflows with modern GitHub Actions pipelines. Continuous Integration now resolves and displays the current plugin version and declared Minecraft version support range, executes comprehensive Gradle builds and unit test suites on pushes to `main` and Pull Requests with automated test report archiving, and uploads compiled shadow JAR artifacts. Introduced a dynamic release cycle commit aggregator generating categorized changelogs from Git history and `gradle.properties` directly into Job Summaries and release bodies. Introduced a chained automated dependency and plugin integration version audit comparing 24 core libraries and integrations against upstream releases in a comparative status table. Consolidated repository diagnostics and project integrity validation (`verify_project_integrity.py`) into the primary CI pipeline, auditing YAML syntax, translation parity (904 keys across English and Spanish), license headers, and pure Java architectural boundaries.
- **Multi-Platform Distribution and Release Pre-Flight Inspection**: Implemented automated distribution tooling (`publish.yml`) supporting Modrinth, CurseForge, and PaperMC Hangar via the official `io.papermc.hangar-publish-plugin:0.1.4`. Release and publication workflows feature a 3-mode execution selector (`Preview`, `Publish`, `Cancel`) providing complete pre-flight inspection of binary SHA-256 checksums, platform tokens, and release notes prior to upload.
- **Server Platform and Upstream Build Auditing**: Centralized supported, legacy, and unsupported platform declarations in `gradle.properties`, with automated real-time build queries against PaperMC Fill v3 API, PurpurMC API v2, and Folia builds to track stable and experimental upstream versions.
- **JUnit 6 Test Platform Alignment and Automated Test Suite**: Resolved transitive version incompatibilities between MockBukkit 4.110.0 and JUnit platform dependencies via `org.junit:junit-bom:6.0.3`, ensuring a fully green automated test suite.
- **Native Bedrock Forms Integration (Geyser and Floodgate)**: Added full native Bedrock Forms (Cumulus) GUI integration for Bedrock players connecting via Geyser and Floodgate. Bedrock players receive touch-optimized forms for menus, block locking, settings, friend management, and admin configuration, with seamless switching back to classic inventory GUIs via `/bp settings`.
- **Experimental Minecraft 1.20.5+ Compatibility**: Lowered descriptor `api-version` to `1.20`, allowing Minecraft 1.20.5 and 1.20.6 servers to load the plugin. While all core protection logic is theoretically compatible (~95-98%), this range is marked experimental; user feedback is appreciated to ensure full stability in subsequent releases.
- **Hot-Path Listener Optimizations**: Redstone, piston movements, block breaks, block burns, and explosion listeners now perform instant early exits via `ProtectedBlockCache`, avoiding expensive NBT deserialization and state snapshots for unaffected blocks.
- **Folia and Paper Scheduler Unification**: All background tasks, search routines, world expiry scanners, and async inventory skull loaders now run exclusively through FoliaLib with thread-safe entity region dispatching.
- **Bounded In-Memory Caching**: Bounded Caffeine caches have replaced unbounded memory structures for player skin profile lookups and offline player candidate queries, preventing memory growth on long-running servers.
- **Expanded Bundled Languages**: Added 5 new language translations (Romanian, Arabic, Ukrainian, Hebrew, and Swedish), bringing out-of-the-box support to 25 languages.
- **Standalone Spigot Deprecation**: Formalized the deprecation of standalone un-forked Spigot in favor of Paper, Purpur, and Folia.
- **Repository Governance and Standardized Commit Convention**: Added formal contribution guidelines (`CONTRIBUTING.md`), project scope definitions (`SCOPE.md`), and AI agent instructions (`AGENTS.md`), alongside a structured commit format (`BPR:<branch>(<type>): <description>`) to ensure consistent repository history and issue-first workflows.
